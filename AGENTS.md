## Workspace and commands

Bun 1.4.2 workspaces, TypeScript, Effect 4; no Nx. Exact dependency pins and `bun.lock` are committed.

- `bun install --frozen-lockfile` — reproducible install.
- `bun run typecheck` — neutral API, Worker and Bun-tooling projects, no emit.
- `bun run lint` — exact-pinned oxlint1.88.0 for JS/TS; `bun run format:check` — non-writing oxfmt check. Oxlint's native correctness/suspicious rules and selected TS style rules replace Biome; the rule sets are not identical. JSON gets oxfmt parsing/formatting, not semantic lint such as duplicate-key detection.
- `bun run format` — pinned oxfmt0.73.0, four spaces and100-column wrapping; preserve logical blank lines. Oxlint does linting only; Biome is removed. The brief, lockfile, generated/vendor files and runtime receipts are excluded.
- `bun test` / `bun run test:unit` — normal cloud-free unit tests in `tests/unit/`, selected by `bunfig.toml`. They use real Effect Layers or explicit inputs and do not import the stack/Worker resource.
- `tests/integration/health.test.ts` — one integration suite; local and cloud are execution targets, not separate suites or a mandatory per-commit matrix. No custom runner or `scripts/` directory.
- `/next-milestone` in Pi — project prompt, after project trust and `/reload`.

## Trusted-PR CI (2026-10-14)

- `.github/workflows/ci.yml` exposes **Offline checks** and **Cloud integration**. Chau must require **both** in the ruleset; skipped dependent cloud is not proof when offline fails. No path/draft bypass, privileged PR event or manual trigger.
- Trusted means same-repository human PR author and non-bot original/triggering actors. Fork/bot PRs fail the cloud trust step before checkout. Repository writers are inherently credential-trusted; this gate cannot sandbox a writer who can edit workflows.
- Approved CI scope: existing-state auth (including temporary state-secret-reading preview), one fresh `it-cloud-*` stage, health and native teardown. Account ID is public YAML; repository `CLOUDFLARE_API_TOKEN` reaches only the native step. Proposed account-scoped Workers Scripts Edit + Secrets Store Read remain **runtime-unverified**. No operator login/cloud run, permission broadening, publication or shared-state bootstrap/upgrade/repair is implied.
- Fresh hosted runners restore no state/profile caches. A run-specific `ALCHEMY_HOME` and project `.alchemy` must be absent before SDK import; `CI=true`, default `updateStateStore:false` and native noninteractive prompts make missing/outdated shared state fail. Recheck these source assumptions when upgrading Alchemy. Environment credentials override `kbpod-dev`; CI does not persist state-auth credentials (`Auth/Resolve.ts`, `Cloudflare/StateStore/State.ts`).
- Native stdout/stderr is discarded. Only the bounded authored report is grammar-checked before summary publication. Never inspect/copy/upload raw SDK files. Report writes cannot block cleanup; missing evidence fails CI. Bun exit0 **and** complete deploy/health/destroy success markers are required.
- A one-way in-memory flag permits destroy after settled deployment success/failure and refuses it while not settled, including initialization that never reached deploy. Bun hook timeout does not interrupt the SDK's promise. Global non-cancelling cloud concurrency reduces overlap, but interruption/runner loss can leak resources and lose reports. No sweep, suite retry, independent removal audit or universal cleanup guarantee.
- Local validation: frozen install, format/lint/typechecks and118 cloud-free units pass; independent code review completed. **First GitHub Actions execution, token sufficiency and this native lifecycle remain unverified.** See `docs/infrastructure-tests.md` and `docs/progress.md` before any follow-up.

## Boundaries and conventions

- `packages/api`: shared schemas and HttpApi descriptions only. No Alchemy, Bun or Node imports.
- `apps/server/src/http.ts`: Effect handler/app Layer; `worker.ts`: sole application Worker edge. Root `alchemy.run.ts`: sole application Stack.
- Future `domain` owns entities/errors; `core` owns cloud-free stages/ports; web and CLI consume the shared contract. Do not create speculative packages before their milestone.
- One runtime per edge; no scattered `runPromise`. Schema at boundaries, typed errors, services/layers. Health has no application failure or settings requirement. Future secrets use `Config.Redacted`; `.env*` and `.alchemy/` stay ignored. Never print secrets.
- Worker/API TS projects exclude Bun types. Oxlint preserves the prior host-import pattern restrictions in these source directories; tests can use Bun. These lint patterns are not a sandbox: bare Node names, `node:` subpaths and `require()` retain the prior rule's gaps. Do not use them to bypass the architectural boundary. Default discovery stays in `tests/unit`; integration is selected explicitly by file path.
- **No module mocking or interception in tests.** Use real Effect Layers/services or explicit pure inputs. Do not replace modules, install module-loader hooks, or patch globals as a substitute. Infrastructure tests must use Alchemy's actual native `Test.make` hooks. Unit tests do not prove native hook scheduling, cloud cleanup or account-wide inventory equality.

## Verified API facts (installed 2026-10-12)

Effect `4.0.3`, Alchemy `2.0.0-beta.81`; installed declarations/source win over docs.

- Effect exports `effect/http`, `effect/http-api`, `effect/cli`, `effect/ai` and other v4 families; don't use Effect-3 platform imports. Later-feature APIs still need fresh verification.
- `Schema.Literal('ok')`, `Schema.Struct(fields)`, `Schema.decodeUnknownEffect(schema)(unknown)`: `effect/src/Schema.ts` (2731, 3585, 1523).
- `HttpApiEndpoint.get(name, path, { success })`; `HttpApiGroup.make(id).add(endpoint)`; `HttpApi.make(id).add(group)`. `HttpApiBuilder.group(api, id, handlers => handlers.handle(name, effectHandler))` builds a typed Layer, provided to `HttpApiBuilder.layer(api)`. Source: `effect/src/http-api/{HttpApiEndpoint,HttpApiBuilder}.ts`.
- The builder needs FileSystem/HttpPlatform/Path/Etag services. `HttpServer.layerServices` supplies them using `FileSystem.layerNoop({})`, Path, weak Etag and HttpPlatform, without a Node/Bun adapter (`effect/src/http/HttpServer.ts:395–405`). Suitable for JSON-only health; no filesystem support is promised. Alchemy's partial platform-stub example omits a required service; do not copy it.
- `HttpRouter.toHttpEffect(appLayer)` yields the request Effect once at construction. `HttpRouter.toWebHandler(appLayer)` returns `{ handler(Request): Promise<Response>, dispose(): Promise<void> }`; always await disposal in tests (`effect/src/http/HttpRouter.ts`).
- `Cloudflare.Worker(id, { main: import.meta.url }, Effect.gen(...))` returns `{ fetch }`; export that resource as the module default. `Alchemy.Stack(name, { providers: Cloudflare.providers(), state: Cloudflare.state() }, effect)` yields it and exposes `worker.url`. Sources: `alchemy/src/{Stack.ts,Cloudflare/Workers/Worker.ts}`.
- `Cloudflare.state()` resolves remote account state and may bootstrap the shared state Worker/DO/Secrets Store; it does not become local merely because dev mode is active (`alchemy/src/Cloudflare/StateStore/State.ts`). Its `loginWithCloudflare` is **not** profile OAuth: it uploads an auth-secret-reading edge preview and caches credentials. Unfinished local bootstrap resumes without a prompt; app plan's dry-run return does not prevent these state side effects. The public state Worker `/version` currently returns version 7; version/name alone do not establish ownership. Host adapters `@effect/platform-bun/node@4.0.3` follow Alchemy's getting-started dependencies and stay outside Worker code.
- Public health contract: `GET /health` → 200 JSON exactly `{"status":"ok"}`, liveness only; unknown paths 404. No auth policy for future application routes is implied.
- Pi project templates live in `.pi/prompts/*.md`; filename is the slash command, loaded after project trust; `/reload` refreshes. Verified Pi 1.1.0 `docs/{prompt-templates,configuration,security}.md`.
